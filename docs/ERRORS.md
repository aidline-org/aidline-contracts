# Error Code Reference

This document provides a complete reference for all Soroban smart contract error codes returned by Aidline (`contracts/aidline/src/errors.rs`).

Integrators and client applications encountering numeric error codes (e.g. `#12`) can use this table to determine the cause of the failure and the required recovery action.

## Error Codes

| Code | Error Variant | Functions Returning Error | What the Caller Should Do |
|:---:|---|---|---|
| **1** | `Unauthorized` | `grant_role`, `revoke_role`, `add_verifier`, `remove_verifier`, `set_admin`, `pause`, `unpause`, `upgrade`, `add_allowed_token`, `remove_allowed_token`, `set_bond_requirement`, `set_bond_withdraw_delay`, `slash_verifier`, `register_with_bond`, `deregister_verifier`, `cancel_campaign`, `reassign_verifier`, `approve_milestone`, `set_platform_fee`, `set_treasury` | Sign the transaction with the authorized address (e.g. admin, role holder, creator, or assigned verifier). For campaigns with multisig verifiers (`threshold > 1`), call `approve_milestone_multisig` with the verifier's address instead of `approve_milestone`. |
| **2** | `CampaignNotFound` | `donate`, `deposit_sponsor_pool`, `apply_matching`, `return_sponsor_pool`, `create_pledge`, `emergency_fast_track`, `approve_milestone`, `approve_milestone_multisig`, `reject_milestone`, `cancel_campaign`, `refund`, `reassign_verifier`, `bump_campaign_ttl`, `extend_campaign_ttl`, `get_campaign`, `is_refundable`, `update_campaign_metadata`, `extend_deadline`, `remaining_to_goal`, `next_milestone`, `refundable_amount`, `effective_status`, `milestone_due_dates` | Verify the `campaign_id` parameter. Ensure the campaign exists and was created successfully. |
| **3** | `DeadlineInPast` | `create_campaign`, `create_campaign_with_due_dates`, `create_multisig_campaign` | Set a `deadline` unix timestamp strictly greater than the current ledger timestamp. |
| **4** | `InvalidMilestones` | `create_campaign`, `create_campaign_with_due_dates`, `create_multisig_campaign` | Provide between 1 and 20 (`MAX_MILESTONES`) milestones. Each milestone amount must be greater than zero, and the sum must fit within an `i128`. If due dates are specified, each due date must be greater than zero, strictly increasing, and before the deadline. |
| **5** | `InvalidAmount` | `set_bond_requirement`, `set_bond_withdraw_delay`, `slash_verifier`, `donate`, `apply_matching`, `set_platform_fee` | Provide a valid amount within bounds. Bond requirements cannot be negative, bond withdrawal delay cannot exceed 90 days (`MAX_BOND_WITHDRAW_DELAY`), platform fee cannot exceed 200 bps (2%), and donation, matching, or slashing amounts must be greater than zero. |
| **6** | `CampaignNotActive` | `donate`, `deposit_sponsor_pool`, `apply_matching`, `create_pledge`, `emergency_fast_track`, `approve_milestone`, `approve_milestone_multisig`, `reject_milestone`, `cancel_campaign`, `reassign_verifier`, `update_campaign_metadata`, `extend_deadline` | Check campaign status via `get_campaign`. The campaign is no longer in `Active` status (it has either been `Cancelled` or `Completed`). Only query view functions or claim refunds if eligible. |
| **7** | `CampaignExpired` | `donate`, `deposit_sponsor_pool`, `apply_matching`, `create_pledge`, `emergency_fast_track`, `approve_milestone`, `approve_milestone_multisig`, `reject_milestone`, `reassign_verifier`, `update_campaign_metadata`, `extend_deadline` | The campaign deadline has passed. Active mutations are closed; donors can claim refunds via `refund` and sponsors can retrieve unused funds via `return_sponsor_pool`. |
| **8** | `GoalExceeded` | `donate` | The campaign is fully funded (`raised == goal`). Do not submit additional donations. |
| **9** | `NotVerifier` | `deregister_verifier`, `create_campaign`, `create_campaign_with_due_dates`, `create_multisig_campaign`, `emergency_fast_track`, `approve_milestone`, `approve_milestone_multisig`, `reject_milestone`, `reassign_verifier` | Ensure the address is an actively registered verifier on the contract registry (via `add_verifier` or `register_with_bond`) and is assigned to the specified campaign. |
| **10** | `MilestoneNotFunded` | `approve_milestone`, `approve_milestone_multisig` | Wait until sufficient donations and/or pledges have been deposited into escrow to cover the milestone payout amount. |
| **11** | `NoMilestonesLeft` | `approve_milestone`, `approve_milestone_multisig`, `reject_milestone` | All milestones for this campaign have already been approved and released. No further milestones remain to approve or reject. |
| **12** | `RefundNotAvailable` | `refund` | Verify refund eligibility using `is_refundable(campaign_id)`. Refunds are only available if the campaign was cancelled, the deadline passed without completion, or an approved milestone due date was missed. |
| **13** | `NothingToRefund` | `refund` | The caller has no refundable contributions recorded for this campaign (either never donated or already refunded). Check `contribution_of(campaign_id, caller)`. |
| **14** | `SponsorPoolExists` | `deposit_sponsor_pool` | A matching pool already exists for this sponsor and campaign. A sponsor can maintain only one active pool per campaign. |
| **15** | `SponsorPoolNotFound` | `apply_matching`, `return_sponsor_pool` | No matching pool exists for the given sponsor on this campaign. Call `deposit_sponsor_pool` before attempting matching or returns. |
| **16** | `InvalidMatchingConfig` | `deposit_sponsor_pool` | Configure `ratio_bps` between 1 and 10,000 (100%), ensure `cap` and `amount` are at least `MIN_SPONSOR_POOL` (`1_000_000`), and set `amount == cap`. |
| **17** | `PoolNotReturnable` | `return_sponsor_pool` | Unused matching pool funds can only be returned after the campaign is closed (cancelled, completed, or expired past deadline). Wait for the campaign to conclude. |
| **18** | `BondRequired` | `register_with_bond` | Check `bond_requirement()` and transfer at least the minimum required bond amount. |
| **19** | `BondNotFound` | `withdraw_bond`, `slash_bond` | The verifier does not have a recorded bond in storage. Verify the verifier address. |
| **20** | `BondNotWithdrawable` | `withdraw_bond`, `slash_bond` | The bond is not in a withdrawable state. Verifiers must first call `deregister_verifier` to enter `PendingWithdrawal`. Slashed or already withdrawn bonds cannot be withdrawn or slashed. |
| **21** | `WithdrawDelayNotMet` | `withdraw_bond` | Wait until the required withdrawal delay (`bond_withdraw_delay()`) has passed since deregistration before withdrawing. |
| **22** | `SlashExceedsBond` | `slash_bond` | Reduce `slash_amount` to be less than or equal to the verifier's remaining bond balance. |
| **23** | `InvalidPledge` | `create_pledge` | Provide a positive `pledged_amount` and ensure the donor has granted sufficient token allowance to the contract before calling `create_pledge`. |
| **24** | `NotEmergencyCampaign` | `emergency_fast_track` | Fast-track advances are only permitted on campaigns created with `CampaignKind::Emergency`. Standard campaigns must use regular milestone approvals. |
| **25** | `AdvanceAlreadyTaken` | `emergency_fast_track` | An emergency advance has already been released for this campaign. The advance can only be used once per emergency campaign. |
| **26** | `AdvanceExceedsEscrow` | `emergency_fast_track` | The requested advance exceeds available unreleased escrow. Wait until donations have entered escrow before calling `emergency_fast_track`. |
| **27** | `InvalidThreshold` | `create_multisig_campaign` | Set the multisig approval threshold $1 \le \text{threshold} \le \text{verifiers.len()}$. |
| **28** | `DuplicateApproval` | `approve_milestone_multisig` | The verifier has already approved this milestone. Another assigned verifier must provide the next approval. |
| **29** | `DuplicateVerifier` | `create_multisig_campaign` | Remove duplicate verifier addresses from the `verifiers` list. Every verifier address must be distinct. |
| **30** | `TokenNotAllowed` | `create_campaign`, `create_campaign_with_due_dates`, `create_multisig_campaign` | Use a token that has been approved by the admin. Check `is_token_allowed(token)` or ask the admin to call `add_allowed_token`. |
| **31** | `Paused` | `donate`, `approve_milestone`, `approve_milestone_multisig`, `emergency_fast_track`, `deposit_sponsor_pool`, `create_campaign`, `create_campaign_with_due_dates`, `create_multisig_campaign` | The contract is paused by the admin for maintenance or emergency. State-mutating operations are temporarily disabled; refunds remain available. Wait for admin to `unpause`. |
| **32** | `DonationsAlreadyStarted` | `update_metadata` | Campaign metadata URI can only be updated before donations begin (`raised == 0`). Once funded, metadata cannot be modified. |
| **33** | `DeadlineAlreadyExtended` | `extend_deadline`, `extend_deadline_by` | A campaign deadline may only be extended once. Subsequent extension requests are rejected. |
| **34** | `InvalidDeadlineExtension` | `extend_deadline`, `extend_deadline_by` | Ensure the new deadline is greater than the current deadline and does not exceed the current deadline by more than 30 days (`MAX_DEADLINE_EXTENSION`), or that `additional_seconds` is between 1 second and 30 days. |
| **35** | `UriTooLong` | `create_campaign`, `create_campaign_with_due_dates`, `create_multisig_campaign`, `update_metadata`, `approve_milestone`, `approve_milestone_multisig`, `reject_milestone` | Ensure metadata, proof, and rejection details URIs do not exceed 256 bytes (`MAX_URI_LENGTH`). Use compact IPFS CIDs or abbreviated URLs. |
| **36** | `ConflictOfInterest` | `create_campaign`, `create_campaign_with_due_dates`, `create_multisig_campaign` | The assigned verifier cannot be the campaign creator or beneficiary. For multisig campaigns, no verifier in the list may be the creator or beneficiary. Designate independent verifiers. |
| **37** | `DonationBelowMinimum` | `donate` | Increase donation amount to meet or exceed the campaign's minimum donation requirement (`min_donation`). A donation below the minimum is only accepted if it reaches or exceeds the remaining goal amount. |
| **43** | `ActionNotFound` | `cancel_action`, `execute_action` | No queued action exists with that id. It may have been executed or cancelled already. |
| **44** | `TimelockNotReady` | `execute_action` | Wait until the action's `eta` (queue time plus `TIMELOCK_DELAY`) has passed. |
| **45** | `ActionExpired` | `execute_action` | The grace period (`TIMELOCK_GRACE_PERIOD`) after `eta` has passed. Cancel the action and queue it again. |
| **46** | `SameCampaign` | `rollover_refund` | Pick a target campaign different from the one being refunded. |
| **47** | `TokenMismatch` | `rollover_refund` | Both campaigns must use the same token. Claim a normal `refund` instead. |
| **48** | `InvalidBeneficiaries` | `create_campaign_with_beneficiaries` | Provide 1 to 10 beneficiaries with positive shares in basis points that sum to exactly 10,000 and distinct addresses. |
| **58** | `InvalidRejectionReason` | `reject_milestone` | Provide a valid `RejectionReason` code (`1` = `IncompleteWork`, `2` = `FraudDetected`, `3` = `InsufficientProof`, `4` = `BudgetExceeded`). |
| **59** | `InvalidMetadataUri` | `update_metadata` | Provide a non-empty metadata URI (`1..=256` bytes). |
